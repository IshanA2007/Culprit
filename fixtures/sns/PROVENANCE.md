# SNS/CloudWatch alarm fixtures (provenance)

These 11 fixtures are the **SNS/CloudWatch** half of the Milestone-3 ingest
contract — the delivery path for the **silent faults** (N+1, cartesian-join,
dropped-index, zero-results) and the **infra dedup** cases (redis-down,
db-stopped) that emit no Sentry event. Each is one SNS HTTPS `Notification` (a
CloudWatch alarm state-change) in the recorder envelope format (`received_at`,
`source`, `resource`, `headers`, `raw_body`). One fixture per silent/infra-dedup
run in `runs/`, linked by that run's `sns:` field. Generated by
`harness/snsfeed.py` (`culprit-harness backfill-sns`).

tCF has **zero alarms today** (`iac/cloudwatch.tf` is two log groups), so there
was nothing to record live. Rather than hand-invent payloads, these are
**reconstructed from real data** — exactly the `harness/deployfeed.py` playbook.

## How they were produced

| Part of the payload | Source | Real? |
|---|---|---|
| Envelope **schema** (SNS `Notification` keys) | AWS's published SNS message format — `harness/snsfeed_inputs/template_notification.json` | ✅ real shape; parity enforced by `tests/test_snsfeed.py` |
| `Message` **schema** (CloudWatch alarm state-change keys, incl. `Trigger`) | AWS's published CloudWatch `AlarmNotification` format (same template) | ✅ real shape; parity enforced |
| `Message` **values** (AlarmName, metric, namespace, dimensions, threshold) | `docs/aws/alarms-proposal.tf` — the alarm suite Culprit proposes — via the fault→alarm map in `harness/snsfeed.py` | ✅ real intended config |
| `Content-Type: text/plain`, `x-amz-sns-message-type` header | the SNS HTTPS delivery contract (the classic gotcha) | ✅ real semantics |
| ids (`MessageId`, subscription arn, `SigningCertURL` hash) | synthesized **deterministically** from the run id | ⚠️ synthetic, no external referent |
| timestamps (`Timestamp`/`StateChangeTime`) | the run's `injected_at` + a documented alarm-evaluation delay (180 s = period×evaluation_periods) | ⚠️ harness-derived |
| `Signature` | **real** RSA over the SNS canonical string | ✅ real crypto (see deltas) |

Anti-leakage: alarm names are generic infra metric names and the `TopicArn` is
`tcf-prod-alarms` — **the payload never names the fault** (the `head_branch:
master` precedent; enforced by `tests/test_corpus.py::test_sns_payloads_never_name_the_fault`).

## Field deltas from a live SNS delivery (documented honestly)

- **`Signature` — real RSA, but signed with OUR keypair, not Amazon's.** A
  locally generated RSA-2048 keypair signs the SNS canonical string. The **public
  cert is vendored** (`harness/snsfeed_inputs/sns_signing_cert.pem`, committed) so
  the verification code path (`culprit/sns_verify.py`) runs offline — verified by
  `tests/test_corpus.py::test_sns_signatures_verify_against_the_vendored_cert`,
  which needs no secret (unlike the HMAC feeds). The **private key is gitignored**
  (`sns_signing_key.pem`) — the deployfeed webhook-secret posture. Delta vs a real
  delivery: the cert is ours, not Amazon's, and `SigningCertURL` points at a
  realistic `sns.<region>.amazonaws.com` URL that is **not** actually fetched in
  fixture mode. **Live mode** fetches the cert from `SigningCertURL` under a strict
  `https` + `amazonaws.com` host allowlist (SSRF guard).
- **`SignatureVersion` = `1`** (RSA-SHA1 over the canonical string). The verifier
  also supports version `2` (RSA-SHA256).
- **ids are synthetic.** `MessageId`, the subscription arn, and the cert-URL hash
  have no external referent; they are derived deterministically from the run id so
  regeneration is byte-stable.

## To record these live instead (the upgrade path)

Stand up an SNS topic + the proposed CloudWatch alarms in a personal AWS account
(or theirs, post-grant), subscribe Culprit's `POST /ingest/sns` over HTTPS
(complete the `SubscriptionConfirmation` handshake), trip each alarm (drive the
fault on the fork), and re-record the genuine deliveries with the webhook
recorder. Real deliveries carry the same envelope shape + `text/plain` +
`x-amz-sns-*` headers, signed by Amazon's cert — a drop-in replacement for these
fixtures that leaves the service code untouched (`FixtureLogsProvider` →
`Boto3LogsProvider`, `docs/aws/aws-access.md`).
